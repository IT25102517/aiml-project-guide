# Member training guide

Run `npm ci`, then `npm run dev` in this folder. Open http://localhost:3000.

Each member chooses their name, downloads their Colab notebook and the starter ZIP, uploads the five CSV files into Colab, and runs the six cells in order. Each guide covers one assigned algorithm and four variants: default and changed parameter settings, each trained on Price and Log_Price. The cells use direct pandas and scikit-learn operations, without custom functions. Instructions are in the app; notebook code only performs the analysis.

The main selection metric is validation RMSE in INR lakhs. MAE and R² provide supporting evidence. This uses one fixed validation split, not cross-validation. All members use the same tuning files and final labelled holdout. The group comparison page reads result CSVs locally and exports a combined table. It also allows a holdout ranking, explaining the limits of selecting on that holdout. Old five-fold result files are rejected because the scores are not comparable.

Assignment 1 files remain the final fitting and evaluation inputs. Two extra tuning files are generated by splitting raw outer-training rows first (25% validation, seed 42) and learning medians, kilometre cutoff, category levels and scaling from development training only. They contain 3,578 development-training rows and 1,199 validation rows. The original 12 features and preprocessing limitations remain. The shared-validation-preparation.ipynb download reproduces these two files from train-data.csv. Final refitting uses the existing 4,777-row processed training file; the 1,194-row labelled holdout stays separate. The processed university file contains 1,234 unlabelled rows used only for predictions.

`scripts/generate-guides.py` invokes `generate-simple-guides.py`, using `model-config.json` and `validation-preparation.py`. Run it with Python, pandas, numpy, scikit-learn and nbformat installed to regenerate the guide content and downloads. It reads the adjacent Data-Preprosses folder. Members do not run the generator: their notebooks use direct Colab filenames and no helper modules. A single validation split and a small manual search are limitations to report.

Run `npm run build` and `npx eslint src` to check the app. Screenshot uploads still depend on the existing configured external storage and database. The screenshot dashboard is a convenience view; its client-side password is not server-side access control. The guide and local CSV comparison work without uploading screenshots.
